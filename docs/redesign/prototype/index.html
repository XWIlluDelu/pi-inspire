帮我看一下 src/resources.ts 里引用索引的缓存键。现在 transcript 向上翻页之后，Resources 面板的引用列表偶尔会闪回旧数据，刷新才恢复。

问题大概率出在引用索引的缓存键：{session, branch view, projection revision} 三元组里，revision 只跟踪 projection 的写版本，而向上翻页是一次 prepend —— 它不改变已有条目的相对顺序，却会让“按 transcript 顺序派生”的索引与面板已挂载的页错位。先读代码确认键的构成，再确认 prepend 路径是否递增 revision。

read src/resources.ts — 212 行

确认了：闪回不是面板的问题，是缓存键的定义漏掉了翻页这一维度。引用索引按 {session, branch view, projection revision} 缓存，而 projectionRevision 只在追加写时递增。向上翻页是一次 prepend：它不改写任何已有条目，所以 revision 不变，键命中，面板直接复用了按旧窗口派生的索引 —— 但其中“最近八条”的头几个位置已经属于新载入的历史。

修复：把 prepend 纳入 revision

最小的正确改法是让 revision 覆盖所有改变投影顺序的操作，而不是只覆盖追加。命中条件可以写成：

hit  ⟺  (s, v, r) = (s′, v′, r′),  r ≔ writes + prepends

改动后的缓存语义对照：

操作revision索引缓存面板表现
追加写 (append)+1保留（键随 revision 前进）正常
向上翻页 (prepend)+1 ← 新增失效并重算不再闪回
branch 切换view 代际更换整体作废正常

有一个测试失败了，但它证明的是旧行为而不是回归：cache-key.test.ts 里 “prepend 不改变缓存键” 的断言需要反过来写。bash 的退出码 1 就来自这条断言（见上方工具批次）。改完断言后 vitest run 本地 47 条全过。
